# Карточки словаря: исследование, источники данных, состав и схема

Дата: 2026-10-21. Цель: развернуть запись словаря umi в листаемую карточку по образцу Shirabe Jisho
для кандзи и слов, только на открытых данных, которые можно распространять внутри приложения.

Цифры с пометкой «замер» посчитаны на свежих выгрузках (JMdict/KANJIDIC2 из jmdict-simplified
3.6.2 от 2026-10-19, KanjiVG r20260714, экспорт Tatoeba от 2026-10-21), остальные взяты из источников по ссылкам.

## 0. Главное коротко

| Вопрос | Ответ |
|---|---|
| Кандзи: откуда данные | KANJIDIC2 (чтения, черты, класс, частотность, ключ), KanjiVG (черты SVG), KRADFILE (части). Всё CC BY-SA, можно |
| Русские значения кандзи | **Открытого источника нет.** В KANJIDIC2 значения только en/fr/es/pt. Переводим с английского сами, помечаем `mt` |

| Частотность слов | Теги приоритета JMdict (`nf01…nf48`, `news1`, `ichi1`, `spec1`, `gai1`) и wordfreq (CC BY-SA 4.0). BCCWJ не годится по лицензии |

| Нельзя использовать | ЯРКСИ, Warodai (и русские глоссы JMdict до получения разрешения), списки частотности BCCWJ, данные WaniKani, аудио Tatoeba |
| ShareAlike | Наши `data/kanji/*.json` и `data/dict/*` становятся производными CC BY-SA 4.0. Код приложения открывать не нужно |

## 1. Что показывают сильные словари

### 1.1 Shirabe Jisho (iOS)

Источники: [App Store](https://apps.apple.com/us/app/shirabe-jisho/id1005203380),
[обзор All Language Resources](https://www.alllanguageresources.com/?p=23828), скриншот экрана 書 от владельца.

**Карточка кандзи**, сверху вниз:

1. Крупный знак.
2. Порядок черт: сетка кадров, на каждом добавляется следующая черта. Больше 6 500 кандзи.
3. Meaning, значения через запятую.
4. ON readings (катакана) и Kun readings (хирагана, окуригана отделена).
5. Nanori, чтения в именах.
6. Note: свободный комментарий, где он есть.
7. Info: Strokes, Grade, JLPT, Frequency, Radical (номер ключа), Components.
8. Compounds: слова с этим знаком, по нажатию открывается карточка слова.

Дополнительно:
- дерево компонентов (с версии 1.9.1);
- поле синдзитай/кюдзитай, то есть новая и старая форма знака (1.11.2);
- уровень WaniKani (1.10.7);
- список похожих кандзи, которые легко перепутать. Обзорщики называют его очень полезным;
- в платных Extras можно менять порядок секций карточки и выбирать, что показывать на флеш-картах: спряжения, примеры, связанные кандзи.

**Карточка слова:**
- запись, чтение;
- линия питч-акцента (с версии 1.9.7);
- озвучка TTS, по отзывам «немного роботизированная»;
- значения по смыслам с частями речи;
- метки JLPT и «частое»;
- кандзи, из которых состоит слово;
- примеры из Tatoeba (147 000 предложений) с фуриганой. Нажатие на слово в примере показывает его значение;
- формы глагола: утвердительная, отрицательная, ます. Поиск по спряжённой форме ведёт к словарной: 買います → 買う.

Поиск: рукописный ввод, который прощает ошибки в порядке черт; поиск по ключам (日 + 月 → 明); маски `*` и `?`.

### 2.2 KANJIDIC2: что есть и чего нет

- `grade`: 1–6 — кёику-кандзи по классам, 8 — остальные дзёё, 9–10 — дзиммэйё. Дзёё (`grade ≤ 8`) ровно **2 136** (замер).
- `freq`: место в газетной частотности (Mainichi), от 1 до 2501. Ранг есть у 2 501 знака.
- `jlptLevel`: **старые уровни 1–4** экзамена до 2010 года. Среди дзёё: 4 → 103, 3 → 181, 2 → 739, 1 → 956, без уровня 157 (замер). Для N5–N1 нужны списки Waller.
- `radicals[classical]`: номер ключа по Канси (1–214). Русских названий ключей нет, их таблицу на 214 строк делаем сами.
- Значения: en (10 384 знака), fr, es, pt. **Русских нет.**
- Особые условия §8 лицензии EDRDG: коды SKIP (Halpern), пиньинь, Four Corner, корейские чтения и т. п. принадлежат своим авторам. Нам эти поля не нужны, не берём их, и вопрос снимается.

### 2.3 JMdict и русские глоссы — **блокер**

- **Сколько:** 69 397 статей с русским переводом из 218 930, то есть около 32 %. Это данные release notes jmdict-simplified, замер совпал. Среди них 18 535 статей помечены как частотные (`common`).
- **Откуда:** глоссы оформлены в стиле БЯРС: «1) писать», «{～な} храбрый», «(перен.)». В 2016 году Jim Breen писал, что словарь Warodai (121 000 статей) переведён в формат EDICT2 и его русские глоссы будут встроены в JMdict. Пробное сопоставление тогда дало ≈ 70 000 совпадений ([письмо](https://www.edrdg.org/jmdict_edict_list/2016/msg00072.html)). **Замер:** в случайной выборке из 1 823 статей хотя бы один длинный русский глосс дословно найден в тексте Warodai у 64,9 %. Остальные отличаются в основном скобками и разметкой.
- **Лицензия Warodai:** CC BY-NC-ND 3.0, то есть некоммерческое использование и запрет переработки ([LICENSE](https://github.com/WarodaiProject/warodai-source/blob/master/LICENSE), [warodai.ru/download](https://warodai.ru/download/)).
- **Что говорит EDRDG:** их лицензия покрывает японскую и английскую части JMdict. Немецкие, французские, русские и прочие переводы «покрыты отдельным копирайтом их составителей» ([licence](https://www.edrdg.org/edrdg/licence.html), [текст у KDE](https://lxr.kde.org/source/education/kiten/LICENSES/LicenseRef-EDRDG.txt)).
- **Вывод:** русские глоссы JMdict нельзя считать CC BY-SA. Если в приложении будет монетизация (подписка, оплата ИИ), мешает NC. Даже без денег мешает ND: обрезать и переформатировать глоссы тоже значит перерабатывать.
- **Что делать:**
  1. Основной путь: русские значения пишем сами. Сначала берём то, что уже есть в `js/data/words.js` (это авторский текст владельца). Остальное переводим с английских глоссов JMdict (CC BY-SA 4.0) через ИИ, вычитываем и ставим пометку `mt`. Такой перевод — производная от CC BY-SA, и выпускаем его под CC BY-SA 4.0.
  2. Параллельно пишем команде Warodai (контакты на warodai.ru и в GitHub WarodaiProject) и в EDRDG. Просим письменное разрешение использовать глоссы в umi. Если разрешат, путь 1 становится запасным.
  3. Свериться с Warodai, чтобы проверить свой перевод, можно. Копировать его формулировки нельзя.
- **Важно для агента, который собирает `data/dict/`:** в BACKLOG сейчас записано «значение по-русски из JMdict». До решения по п. 2 так делать нельзя. Если глоссы уже собраны, их нужно хранить в отдельном поле с источником `warodai` и **не публиковать**.

### 2.4 Tatoeba: пары ja–ru

| Показатель (замер) | Значение |
|---|---|
| Японских предложений всего | 248 939 |
| Прямых пар jpn → rus | **31 616** |
| Уникальных японских / русских предложений в парах | 28 515 / 29 531 |
| Дзёё-кандзи, у которых есть хотя бы 1 / 3 / 10 пар | 1 896 / 1 582 / 1 115 из 2 136 |
| Японских предложений под CC0 | 2. Всё остальное CC BY 2.0 FR |
| Русских предложений под CC0 | 23 076 из 1 231 016 |
| Самые частые авторы японских предложений в парах | bunbuku 7 882, tommy_san 4 487, small_snow 3 608, без владельца 3 299 |

- **Лицензия:** CC BY 2.0 FR. Атрибуция ставится каждому предложению: нужно назвать автора ([wiki Tatoeba](https://en.wiki.tatoeba.org/articles/show/using-the-tatoeba-corpus)). Практичный вариант: храним ID обоих предложений и имена авторов. В карточке под примером даём мелкую ссылку «Tatoeba №…», плюс общий экран «Источники».
- **Не берём** косвенные пары через английский (jpn → eng → rus): это перевод перевода, качество низкое.
- **Не берём аудио:** лицензии у авторов разные, часто NC. Озвучку делаем через TTS браузера (`speechSynthesis`, `ja-JP`).
- Часть японских предложений пришла из корпуса Танаки. Там бывают кальки и ошибки. Предложения с тегом `@needs native check` и короче 4 символов лучше отбрасывать.

### 2.5 Частотность для выбора популярных слов

| Источник | Что это | Лицензия | Годится |

Формула ранга для отбора 6 000 слов: `score = nf (1…48, нет — 60)`, минус бонус за `ichi1` или `spec1`. При равенстве сортируем по wordfreq. Слова из списков JLPT N5–N3 добавляем принудительно.

### 2.6 Уровни JLPT

- Официальных списков нет с 2010 года: организаторы экзамена их не публикуют. Все списки неофициальные.
- Списки Jonathan Waller (tanos.co.uk) распространяются под CC BY. Зеркала: [Bluskyo/JLPT_Vocabulary](https://github.com/Bluskyo/JLPT_Vocabulary) (JSON/CSV) и [davidluzgouveia/kanji-data](https://github.com/davidluzgouveia/kanji-data) (поле `jlpt_new`, MIT). **Поля `wk_*` из kanji-data не брать:** это данные WaniKani, условия их API не разрешают распространение.
- Сайт tanos.co.uk при проверке 2026-10-21 не открылся (DNS). Точную версию CC BY нужно сверить, когда сайт заработает. Пока атрибутируем как «CC BY, Jonathan Waller».
- В интерфейсе подписываем «JLPT N3 (неофиц.)» или ставим сноску на экране источников.

### 2.7 Питч-акцент (на потом)

Kanjium `accents.txt` выпущен под CC BY-SA 4.0. Но происхождение самих данных об ударении задокументировано плохо: автор пишет, что это его собственная база. Перед использованием стоит проверить происхождение. Wadoku (японско-немецкий) выходит под своей лицензией, в MVP его не берём.

### 2.8 Что использовать нельзя

## 3. Рекомендуемый состав карточек

### 3.1 Карточка кандзи

| # | Секция | Содержание | Взаимодействие | Этап |
|---|---|---|---|---|

## 4. Схема данных

### 4.1 Файл кандзи `data/kanji/<hex>.json` (имя — код Unicode в нижнем регистре без `U+`: `66f8.json`)

Текущая схема агентов:
```
{"k","strokes","grade","jlpt","freq","radical":{"c","n","ru"},"parts":[],"on":[],"kun":[],"nanori":[],
 "ru":[],"en":[],"svg":[...],"words":[{"w","r","m"}],"sents":[{"jp","ru","src"}]}
```

**Вывод:** для MVP схема годится. Ниже правки, по важности. Ни одна не ломает то, что уже собрано: поля только добавляются, и смысл существующих уточняется.

| # | Поле | Правка | Зачем |
|---|---|---|---|
| 1 | `v` | Добавить `"v":1` | Версия схемы, чтобы клиент отличал старые файлы |
| 2 | `jlpt` | Число **5…1 = N5…N1** из списков Waller, `null`, если нет. Старый уровень KANJIDIC не класть | Иначе путаница: в KANJIDIC2 «4» значит самый лёгкий уровень |
| 3 | `freq` | Ранг 1…2501 или `null` | Явно описать формат |
| 4 | `grade` | 1–6, 8 (дзёё вне школы), 9/10 (дзиммэйё) — как в KANJIDIC2 | Подпись делает клиент |
| 5 | `radical` | Добавить `"v"`: форму ключа, как она выглядит в знаке (氵 для 海, когда `c` = 水), и `"ja"`: японское название (さんずい), если есть | Shirabe и Jisho показывают именно вариантную форму |
| 6 | `parts` | **Заменить подстановки KRADFILE на настоящие компоненты:** 汁→氵, 化→亻, 乞→𠂉, 込→辶, 忙→忄, 扎→扌, 犯→犭, 艾→艹, 尚→⺌, 杰→灬, 礼→礻, 初→衤, 阡/邦→阝, 老→耂, 个→𠆢, 疔→疒 и т. д. Замер: для 海 KRADFILE выдаёт `["汁","母","毋","乞"]` | Иначе в карточке появятся «части», которых в знаке нет |
| 7 | `parts` | Русские названия не-кандзи компонентов хранить в одном общем файле `data/kanji/_parts.json` (`{"⺌":"малый сверху","𠂉":"…"}`), а не в каждом знаке | Нажатие на часть работает без лишней загрузки |
| 8 | `kun` | Хранить в формате KANJIDIC: `か.く`, `-が.き`. Разметку делает клиент | Окуригану можно выделить цветом |
| 9 | `ru`, `en` | Добавить `"ru_src"`: `"own"` или `"mt"` | Честная пометка машинного перевода, как в BACKLOG |
| 10 | `svg` | Оставить. Добавить `"nums":[[x,y],…]` — позиции номеров черт из группы `StrokeNumbers` KanjiVG. Эта группа есть только в отдельных SVG из `main.zip`; в сводном `kanjivg.xml` её нет (замер) | Сетка кадров с номерами черт, как в Shirabe |
| 11 | `words[]` | Расширить до `{"w","r","m","id","kr","jlpt"}`. `id` — номер статьи JMdict (`seq`); `kr` — чтение именно этого знака в слове (из JmdictFurigana / поля `k`); `jlpt` — для сортировки | По `id` открывается карточка слова. По `kr` слова делятся на группы «ОН/КУН» и фильтруются по нажатию на чтение |
| 12 | `words[].m` | Не брать из русских глоссов JMdict (§2.3). Брать из `words.js`, иначе из словаря `data/dict`, иначе `mt` | Лицензия |
| 13 | `sents[].src` | Сделать объектом: `{"t":[jpnId,rusId],"a":["bunbuku","…"]}`. `a` — авторы японского и русского предложений | CC BY 2.0 FR требует назвать авторов. По ID строится ссылка на tatoeba.org |
| 14 | `sents[]` | Добавить `"w"`: какую форму слова со знаком выделить в предложении (например 書いて) | Подсветка в примере |
| 15 | позже | `"var"` (кюдзитай и прочие варианты из KANJIDIC2), `"sim"` (похожие кандзи), `"note"` | Секция «Ещё» |

Пример (замер на 書 с 12 словами и 3 примерами):

```json
{"v":1,"k":"書","strokes":10,"grade":2,"jlpt":5,"freq":169,
 "radical":{"c":"曰","v":"曰","n":73,"ja":"ひらび","ru":"говорить"},
 "parts":["日","聿"],"on":["ショ"],"kun":["か.く","-が.き","-がき"],"nanori":["かき"],
 "ru":["писать","книга","документ"],"ru_src":"mt","en":["write"],
 "svg":["M30.74,20.63c2.01,0.49,3.84,0.58,5.91,0.39c9.45-0.89,…","…"],"nums":[[x1,y1],[x2,y2],"…"],
 "words":[{"w":"教科書","r":"きょうかしょ","kr":"しょ","m":"учебник","id":1237020,"jlpt":4}],
 "sents":[{"jp":"手紙を書いています。","ru":"Я пишу письмо.","w":"書いて","src":{"t":[123,456],"a":["bunbuku","…"]}}]}
```

### 4.2 Словарь слов `data/dict/`

Ленивая загрузка в двух уровнях:

```
data/dict/index.json       — грузится при открытии поиска
data/dict/e/<NN>.json      — шарды полных статей по 250 слов (00…23 для 6000 слов)
data/dict/LICENSE          — CC BY-SA 4.0 + перечень источников
```

`index.json` — массив массивов (так компактнее объектов):
```json
{"v":1,"cols":["id","w","r","m","jlpt","rank","shard"],
 "rows":[[1358280,"食べる","たべる","есть, кушать",5,312,"01"]]}
```

Статья в шарде:
```json
{"id":1358280,"w":"食べる","r":"たべる",
 "alt":[{"w":"喰べる","rare":true}],"ra":[],
 "k":[{"c":"食","r":"た"},{"c":"べる"}],
 "pos":["v1","vt"],"common":true,"jlpt":5,"rank":312,
 "senses":[{"pos":["v1","vt"],"ru":["есть","кушать"],"ru_src":"own","en":["to eat"],"misc":[]},
           {"ru":["жить на что-л."],"ru_src":"mt","en":["to live on (e.g. a salary)"]}],
 "sents":[{"jp":"…","ru":"…","w":"食べ","src":{"t":[1,2],"a":["…"]}}]}
```

- `k` в том же формате, что `BUILTIN_WORDS` в `js/data/words.js`, чтобы переиспользовать рендер фуриганы.
- `pos` — коды JMdict (`v5k`, `v1`, `adj-i`, `adj-na`, `vs`…). Русские подписи держит клиент. Класс глагола берём оттуда же, он нужен для таблицы форм.
- Формы глагола **не хранить**: их строят правила тренажёра.
- `rank` — позиция по формуле из §2.5 (1 = самое частое).

### 4.3 Оценка размеров (замер на реальных данных)

| Набор | Сырой JSON | gzip -9 | Как грузится |
|---|---|---|---|
| Один файл кандзи (書: 12 слов, 3 примера, SVG) | 2,8 КБ | 1,4 КБ | По открытию карточки |
| SVG черт одного дзёё-кандзи | в среднем 0,9 КБ, максимум 2,2 КБ | — | Внутри файла |
| Все 2 136 файлов кандзи | ≈ 6 МБ | ≈ 3 МБ (сумма по файлам) | Никогда целиком |
| `index.json` для 6 000 слов (id, w, r, краткое m, jlpt, rank) | ≈ 0,55 МБ | ≈ 0,16 МБ | Один раз, кэшируется |
| Полные статьи 6 000 слов, до 3 смыслов, без примеров | 1,08 МБ | 0,27 МБ | Шардами по ≈ 45 КБ / 11 КБ gz |
| + по 2 примера на слово | + ≈ 1,8 МБ | + ≈ 0,6 МБ | В тех же шардах |

Про gzip:
- GitHub Pages, Netlify, Vercel и nginx с `gzip on` сжимают `application/json` на лету. Файлы кладём несжатыми. Если хостинг не сжимает, по сети пойдут сырые размеры.
- JSON писать без пробелов (`separators=(',',':')`, `ensure_ascii=False`). Кириллица и кандзи в UTF-8 весят меньше, чем `\uXXXX`.
- Если кто-то предложит собрать все кандзи в один бандл: 3 МБ gzip — много для первого открытия мини-аппа в Telegram. Ленивые файлы по 1–2 КБ лучше. HTTP/2 и кэш WebView делают повторные открытия мгновенными.
